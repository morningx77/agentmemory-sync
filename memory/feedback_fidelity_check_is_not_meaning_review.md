260913 UX Korea 리뷰 PPT 25장. 인용 33·수치 39 기계대조 불일치 0, COM 실렌더 결함 0으로 "완료" 보고했는데, 사용자가 연달아 짚었다:
- 3p 제목 "우리 방식의 구조화" → 무엇을 구조화하는지 안 읽힘(작성자는 뜻을 알아서 못 느낌)
- 3p 인용 "판단이 흩어져 있는 한 AI는 편차를 증폭" → 세 인사이트를 묶는다며 넣었으나 1·3과 연결 약함, 인사이트1 "평균 수렴"과 모순처럼 보임, 13p와 중복
- 셀프 재점검에서 5p 노트 "모델을 바꾸는 것보다" = 출처에 없는 비교(과장)
사용자: "3페이지만의 문제가 아닌 것 같은데? 왜 이렇게 놓치는 게 발생한 거지?"

**Why:** 내 검증은 전부 **충실도**(원고→산출물 옮김이 정확한가)였고 **의미**(원고가 청중에게 맞는 말인가)는 한 번도 안 봤다. 원고가 틀리면 틀린 채로 완벽히 옮겨진다. 원고를 쓴 사람이 검수까지 해서 모호함이 안 보였고, 직전 덱 요소를 새 구조로 옮기며 "이 자리에서도 역할을 하나"를 재심하지 않았다.

**How to apply:**
- 발표물·보고서·원고는 **제작 착수 전(원고 단계)** 에 의미 검수를 한다. 산출물 완성 후가 아니라
- 검수는 **작성자가 아닌 눈** — 서브에이전트 2관점(A 청중 이해·논리·중복·모순 / B 사실·근거·과장·귀속), Opus, 읽기 전용
- 체크리스트: 제목만으로 뜻이 통하나 · 설명 없는 용어 · 요소가 왜 그 자리에 있나 · 장 간 모순/중복 · 근거보다 센 말(비교 대상이 출처에 있나) · 노트↔장표 일치
- 기존 산출물에서 요소를 재사용할 때는 "새 구조에서 이 요소의 역할"을 한 줄로 적고, 못 적으면 뺀다
- "검증 완료" 보고 시 **무엇을 검증했고 무엇은 안 했는지**(충실도 vs 의미)를 구분해 말한다
