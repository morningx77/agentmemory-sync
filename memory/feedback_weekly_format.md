주간업무 보고서는 테이블 형식이 아닌 들여쓰기 목록 구조로 작성한다.

**Why:** 사용자가 "테이블은 너무 자동으로 생성된 느낌"이라고 피드백. U+00A0(non-breaking space)는 "너무 촘촘해 보인다"고 피드백 → U+3000(전각 스페이스)으로 변경.

**How to apply:**
- 들여쓰기: U+3000(전각 스페이스) 사용. U+00A0 사용 금지
- 계층: `◾ 그룹` → `　• 항목` → `　　◦ 속성` → `　　　- 세부`
- 이슈/리스크 섹션도 테이블 아닌 목록+들여쓰기
- 선후관계 명확, 자료 연결 필수 (본부장 요구사항)
- **금주 실적·신규 업무**는 `◦ 산출물:`(그 업무로 만든 결과물)로 적는다. **차주 계획·이슈**의 `◦ 근거:`(이유·참조)는 산출물이 아니므로 그대로 둔다. 실적의 이유·배경은 `◦ 사유:`
- **산출물은 로컬 경로(05_notes/… 등)가 아니라 관계자가 접근 가능한 공유 링크**(구글 드라이브·Figma URL 등)로 적는다 — 로컬 경로는 "내 PC에 있다"는 의미라 자산이 아님. 옵시디언 노트 등 내부 관리용은 산출물에서 제외. (Why: 사용자가 "로컬 경로는 의미 없다, 무엇이 만들어지고 자산화됐는지 명확히"라고 피드백)
- 구글 드라이브 업로드는 base64 대신 **텍스트(text_content)로** 올린다 — 긴 base64는 정책 필터 오탐으로 차단될 수 있음. 회사 계정 공유 폴더: 내 드라이브 > 제품기획 (rnd@ispark-ai.com)
- **개인 지식관리 작업**(옵시디언 지식 노트 갱신·동기화 등)은 주간보고 실적·산출물에 **아예 넣지 않는다** — 대외 보고 대상이 아닌 개인 프로세스. (사용자 피드백)
- **내부 기호 `§N`(기획서 섹션 번호)은 주간보고에 쓰지 않고 "기획서 N장"처럼** 관계자가 바로 이해할 표현으로 풀어쓴다. (사용자 피드백)
- **단정적·부정적 표현은 순화**한다 — 예: '불가' → '어려움', '실패' → '미흡/보완 필요'. 보고서 톤은 사실을 전하되 부드럽게. (사용자 피드백)
