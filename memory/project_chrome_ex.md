# 260624_Chrome_Ex — 크롬 확장 자동화 프로젝트

위치: `03_projects/260624_Chrome_Ex/01_docs/`. 담당 세션 별칭=[[크롬]] (크롬 확장 개발 전문가).

## 배경/동기
- 기존 '딥노트'는 Playwright(별도 브라우저)로 네이버 로그인·포스팅 → **봇으로 인식되는 문제** + **네이버 검색 누락(검색 노출 제외) 경험**.
- 전환 방향: **실제 사용자 크롬 프로필을 쓰는 MV3 확장**으로 포스팅/자동화 → 봇 탐지 회피.
- 목적 A: **API 비용 없이** Gemini 등 웹 UI를 자동화로 활용(입력→실행→결과 회수).
- 목적 B: 네이버 자동 포스팅 시 **검색 누락 회피**가 진짜 핵심 동기.

## 핵심 기술 결론 (1차 리서치 확정)
- 일반 content script `dispatchEvent`는 항상 `isTrusted=false` → 네이버 정밀 입력검증 통과 못함.
- 해결: **`chrome.debugger` + CDP `Input.dispatchKeyEvent/dispatchMouseEvent`** → `isTrusted=true` 진짜 입력(MV3 공식 허용 예외).
- ⚠️ 함정: ① attach 시 디버깅 경고 배너 노출(닫으면 세션종료) → 완전 무인 자동화 부적합, 반자동 도구가 현실적 ② 2026 탐지는 navigator.webdriver가 아니라 **CDP 켜짐 자체(Runtime.enable 흔적)** 를 표적. 봇처럼 보이는 핵심은 결국 규칙적 타이밍·대량반복.

## ★ 0순위 결론 (전략 분기 — 매우 중요)
- **네이버 검색 누락의 원인은 봇/자동화 탐지가 아니라 콘텐츠 품질·유사문서 중복·색인 보류다.** (14개 통념 반박, 강하게 수렴)
- 파이프라인: 수집→색인(누락 1차 발생)→랭킹(C-Rank/DIA=순서만, 누락 아님). 유사문서 필터는 블로그·카페·뉴스 가로질러 원본1개만 노출.
- **함의: 확장으로 isTrusted 입력 완벽히 해도 검색 누락은 안 풀린다.** 검색노출=콘텐츠 독창성·비중복 설계로 풀 것.
- 단 봇탐지 회피는 여전히 유효(검색누락이 아닌 '계정제재·캡차·로그인차단' 리스크 대응). → 두 문제 별개, 둘 다 대응.
- "자동화 행위 자체가 누락신호"는 입증 안 됨. 자동포스팅 위험은 산출물의 저품질·유사문서.
- 리포트: `01_docs/00_네이버_검색누락_원인규명_리서치_260624.md`
