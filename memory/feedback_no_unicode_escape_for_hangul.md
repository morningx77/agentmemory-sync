**파일에 쓰는 한글은 리터럴로 쓴다.** `촬` 같은 유니코드 이스케이프로 쓰지 않는다. 셸 인코딩이 걱정이면 **셸을 안 거치는 도구(Write/Edit)** 를 쓴다 — 이스케이프는 해법이 아니라 다른 사고의 입구다.

**Why:** 260904 실사고 — Bash + python 으로 파일을 편집하며 한글을 `\uXXXX` 로 적다가 `췬`(췬)을 썼다(「촬」은 `촬`). **「3장 촬영됨」이 「3장 췬영됨」으로 라이브에 나갔다.** 더 나쁜 것은 **스크린샷으로 눈검증까지 하고도 못 봤다** — 사람은 글을 읽을 때 보정한다. 내 정규식이 「장 촬영됨」을 못 찾았을 때도 나는 그것을 *검사식 결함*으로 읽고 넘어갈 뻔했고, 마스터가 같은 것을 못 찾았다고 다시 말해 준 뒤에야 글자를 봤다. CNOTE 팀은 이것을 규율 **F2-15**(「본문은 사람이 읽는 형태를 떠나지 않는다」 — 백슬래시·백틱 셸 경유 금지 + 한글 `\u` 금지)와 **F2-16**(「본 대로 복사해 붙인다」)으로 등재했다. 같은 형태가 그날 하루에 다섯 번 났다.

**How to apply:**
- 한글이 든 파일 편집은 **Write/Edit 도구**로 한다. Bash heredoc + python 치환은 이스케이프를 부르고, 이스케이프는 오타를 감춘다.
- **글자는 눈으로 검증하지 말고 기대값과 기계로 대조한다.** 렌더 문자열 목록을 만들어 `count()` 로 하나씩 맞춘다 — 눈검증은 레이아웃·색·여백용이고 철자용이 아니다.
- 검사식이 "못 찾았다"고 할 때 **검사식 결함으로 단정하지 말 것**. 대상 문자열이 실제로 무엇인지(코드포인트까지) 먼저 본다.
