2026-08-10 CNOTE 완결성 체크리스트가 **v1.1(104→105항목)** 로 개정됐다. 사용자 승인 완료. 근거=저널 542행 · `_master_changelog [260810-3]` · 회고 R-5.

**계기 실사고**: v0.34.0 `§3-5` 판정 조건표가 *"매칭 안 됨 = 행 없음"* 이었는데, 하류 **OUTBOX 자동매칭(v0.29.2)** 은 같은 건을 *"customers 0건 = 확인 필요"* 로 큐에 넣어 ✨새 거래처로 취급하고 있었다. **한 사건에 두 화면이 다른 말을 했다.** 원인="행 없음"이 ⓐ판정 불가와 ⓑ판정됐으나 대상 미발견 **두 뜻을 겸한 것**.

- **신규 `A3-05` 하류 대조** — 판정·분류 규칙 확정 **전에** 그 결과를 소비하는 하류 화면·문서의 기존 규칙과 **1:1 대조**. 특히 **"아무것도 안 함"(행 없음·배지 없음·큐 제외) 케이스**를 하류가 어떻게 처리하는지. ★**게이트가 구조적으로 못 잡는다** — 양쪽 다 문법 정상·마커 정합이고 어긋난 건 *의미*뿐이라 `run_gates`·`npm run gate`에 안 걸린다 → 자동화 하향 불가, 판단 규칙으로만 존재 가능.
- **`B1-05` 확장(신규 0건)** — 빈 상태에 두 의미를 겸하게 하지 말 것. ⓑ는 **"판정 + 되돌리기"로 단일화**(AI가 "아니다"라고 단정하는 케이스를 남기지 않는다). 역방향 버튼은 **넣지 않는다** — 언제 띄울지 규칙을 만들 수 없다(전부=소음 / 조건부=그 조건이 곧 판정이라 순환).
- ★기획 제안은 A3·B1 **2곳 추가**였으나 **A3-05 하나로 통합**하고 "B1이 판정 규칙을 포함하면 교차 적용"을 문구에 넣어 **순증 +1로 억제**했다(§5-5 ⓒ 선반영).

**⚠미이행 부채**: §5-5 *"총량은 늘리지 않는다"* 상계 — **다음 분기 다이어트에서 1건 이상을 게이트 하향 또는 폐기**해야 한다. 경고는 체크리스트 v1.1 버전 표와 `_master_changelog` **두 곳**에 있다.

**How to apply:** 판정·분류 규칙(무엇을 X로 본다/안 본다)을 새로 설계할 때 **A3-05를 먼저 적용**한다. 다음 규칙 다이어트 시 **이 상계를 제일 먼저 확인**한다 — 미루면 [[cnote-process-tiering-proposal]] ⓒ(규칙 단방향 누적)가 그대로 재발한다.
