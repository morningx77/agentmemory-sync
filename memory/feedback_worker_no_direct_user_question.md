CNOTE 멀티에이전트에서 **워커 세션은 사용자(사장님)에게 직접 묻지 않는다.** `AskUserQuestion` 같은 질문 도구도, 보고 끝의 「올릴까요?」「정리할까요?」도 여기에 해당한다. 확인·판정이 필요하면 **저널에 `handoff_to: 관제(ag마스터 등)`로 올리고, 답을 기다리며 멈추지 않고 할 수 있는 다음 일을 한다.** 사장님께 여쭙는 것은 **관제만** 한다.

**Why:** 260913 에 같은 사장님 판정(A·C)이 **두 창에서 다르게** 나왔다(ag마스터 4896 ↔ ag기획 창) — 여러 세션이 각자 여쭈면 답이 갈리고, 어느 쪽이 반영됐는지 관제가 모른다. 사장님 토큰도 여러 창에서 나눠 쓰인다. 저널 4908 에서 규율로 적고 4912 에서 전체 공지(정본 프로세스 문서 §「사장님 확인 요청은 관제만 한다」 신설)로 승격됐다. ag스토리북은 같은 날 W2 계획서 승인을 질문 도구로 받았고, 보고마다 사장님 확인 목록을 사용자에게 적어 드렸다 — 이 규칙에 어긋나는 형태였다.

**How to apply:**
- 판정이 필요한 자리 = 저널 `type: blocked` 또는 `note` + 근거 + **내가 고르지 않은 이유**. 선택지를 사용자 화면에 늘어놓지 않는다.
- 루트 CLAUDE.md 의 「계획서 → 사용자 검토 → 실행」은 **워커 세션에서는 관제 검토로 갈음**한다 — 계획서는 쓰되 승인은 저널로 관제에 청구하고, 배분이 곧 착수 승인이다(4853 같은 `assign`).
- 사용자가 이 창에 **직접 지시**한 것(예: 「모니터 활성해줘」)에는 그대로 답한다 — 금지는 「내가 먼저 묻는 것」이다.
- 보고 말미는 질문이 아니라 **상태로 끝낸다**(「대기 중 · 배분이 오면 착수」).
